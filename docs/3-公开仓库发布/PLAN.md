# 发布计划

1. 核对 gh 当前账号和仓库名是否可用。
2. 扫描全部可达 Git 历史中的 blob，与本机已知 DeepSeek/Claude 凭据及常见密钥模式比对；不在日志或文档输出密钥。
3. 完善根目录环境配置、缓存、日志和临时运行文件的忽略规则，并按目录拆分 Python 缓存规则。只保留占位符 .env.example。
4. 使用真实 git check-ignore 检验敏感文件被忽略、示例和源码仍可提交；配置变更进行独立审查。
5. 本地提交并快进合并后再次检查完整历史，使用 gh 创建 public 仓库并推送 main。
6. 核对远端可见性、main 提交 SHA 和文件树，确认私有配置没有上传。

本轮不修改运行时代码、不改写已有提交历史、不发布 API 凭据，也不调用付费模型做无关测试。
