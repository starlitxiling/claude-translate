# 提交前审查

## 方式

采用 review-loop 重档五个角度，由本地 Codex CLI 在独立上下文只读审查。常规角度使用 gpt-5.6-terra / medium，并发和生命周期使用 gpt-5.6-sol / high。未向审查进程提供密钥或付费 API 访问任务。

## 首轮发现及处理

| 发现 | 处理与验证 |
| --- | --- |
| 当前项目同名模块可能遮蔽组件 | 启动脚本、服务和 Hook 使用 `-I`；真实同名文件回归先失败后通过，默认命令真实 API 测试也在该目录执行 |
| 前置全局选项可能绕过原生升级拦截 | 使用 NativeArguments 区分选项值与子命令，真实原生 `update --help` 测试验证拦截 |
| 原生管理子命令名单不完整 | 补齐 attach、gateway、respawn、ultrareview，使用缺失翻译配置的真实命令帮助验证直通 |
| 原版别名变更后停用可能丢失恢复记录 | 停用前核对别名归属，冲突时保留入口和状态；真实文件回归通过 |
| 状态读取未进入启停的文件锁域 | 路径解析进入相同 flock 临界区；真实子进程等待锁的回归通过 |

## 复审

复审发现组合短参数 `-cn` / `-pn` 尚需处理；补齐逐字符解析、附加值与下一参数的区别，新增真实原生命令帮助回归。两个发现该问题的独立 reviewer 最终均返回 clean。其余三个角度复审为 clean，无遗留高置信 correctness finding。

主会话最终执行 47 项测试，全部通过（38 项本地、9 项真实 API）；Ruff 和格式检查通过。审查进程以源码核对和原生只读帮助探针为主，未独立重复付费 API 验证。
