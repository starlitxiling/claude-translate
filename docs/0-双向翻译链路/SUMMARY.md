# 开发总结

## 开发项背景

用户希望在原生 Claude Code 终端中输入中文，经独立翻译层转为英文交给 Claude，并将英文回复翻译成中文显示。组件需要独立启停，能够方便取消，翻译引擎指定 DeepSeek Flash。

## 实现方案

- 提供独立 `claude-zh` 启动入口，临时注入 UserPromptSubmit 和 MessageDisplay hooks、本地随机端口及访问令牌；退出后清理进程与临时文件。普通 `claude` 保留原行为。
- 输入 Hook 登记用户原文与英文译文，代理只精确替换对应用户消息；英文 Claude 响应原样传给客户端，显示 Hook 才翻译成中文。工具调用数据、图片和系统提示保持原样。
- 使用官方 `deepseek-flash` API、关闭思考模式。对代码围栏、行内代码、链接和路径做本地保护及完整性检查；跨显示批次维护代码围栏状态。
- 配置与运行时依赖分离；HTTP 客户端、数据库连接和组件通过构造参数传递。密钥位于权限 600 的专用 `.env.local`，译文缓存使用同样权限的 SQLite 文件。
- 原上游拒绝 Claude Code 2.1.300 及以上。经用户明确授权，将现有 2.1.307 替换为 2.1.299，仅新增全局 `env.DISABLE_AUTOUPDATER=1` 保持兼容版本。原二进制保存在 `~/.local/share/claude/backups/2.1.307`；设置备份为同目录的 `settings-before-downgrade-20261026-105127.json`。

### 验证证据

- 本地契约与生命周期测试 15 项通过；真实 API 测试 8 项通过，其中翻译样本按三轮重复运行，每轮覆盖双向翻译、代码保护、指令作为数据处理及代码生成请求的纯翻译。真实 HTTP trace 同步测试验证了不同文本可并发发送，以及最终显示批次之后的等待者不会重新打开状态。
- 真实 Claude Code 2.1.299 的 print 模式通过：输入登记、消息替换、显示翻译均触发，输出包含中文，测试前后全局 settings 哈希相同。
- 真实交互式 TTY 通过：中文输入得到中文解释、原样 `git status` 代码块和中文总结，`/exit` 正常退出。
- 跨进程恢复会话通过：`--resume` 后的新输入和已有历史输入共替换 2 个消息块，输出中文且显示失败数为 0。
- 英文原始回复与中文显示已分别核对：会话 `87aa4835-60a7-4653-be3a-5df26e410a29` 的原始 assistant 文本以 `The read-only check confirms...` 开头，终端显示中文；本轮统计为登记 1、替换 1、模型请求 1、显示批次 1、显示失败 0。
- SIGTERM 生命周期测试使用真实 Claude CLI，确认本地代理退出、临时运行文件删除。格式与 Ruff 检查通过。
- 独立 wheel 安装后的命令通过真实上游测试：登记 1、替换 1、模型请求 1、显示批次 1、显示失败 0。安装包不含密钥或本地配置，五角度独立复审均为 clean。

## 局限性

- 已验证 macOS 和 Claude Code 2.1.299；Linux、其他版本及不同网关配置需要另行实测。
- 只支持 Anthropic Messages 上游，不支持云端、后台、`--bare`、自定义 `--settings` 或其他云厂商原生协议。
- 模型原始会话记录、工具结果、权限菜单不翻译；未登记的旧会话中文历史保持原样。未加代码标记的日志或代码不能保证自动识别为字面内容。
- 翻译增加时延与 API 费用；超时或输出校验失败时，输入被阻止，回复显示英文。模型别名由 DeepSeek 更新，不承诺固定权重。
- 版本降级及关闭自动更新独立于翻译组件，卸载组件不自动撤销这两项环境操作。
