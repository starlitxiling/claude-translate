# 开发总结

## 开发项背景

用户希望保留 subagent 内部英文处理，只在最终结果交回主会话时翻译，避免为内部过程反复调用翻译服务。

## 实现方案

- 子代理输入和显示事件通过 agent_id 或明确子代理 transcript 路径识别并跳过；主会话自定义 agent_type 不会被误判为子代理。
- 新增 SubagentReports：顶层 Agent 前台完成时显示中文报告；后台只保存英文结果，等主会话收到完成通知再显示。SubagentHandback 取真实 message，而不是取结束语或“已交回”的提示。
- 中文副本经主会话 Hook 的 systemMessage 显示。没有改写 tool_result、Handback 参数或 additionalContext，主模型仍使用英文报告。已登记的后台任务通知也不进入用户输入翻译。
- 同一交接去重，恢复同一个代理的新调用可重新显示相同内容。状态按 session/agent 分隔、使用每个代理自己的锁，最多保留 128 个状态；失败保留英文，不阻止任务。
- 减短字面片段占位符并检查源文本碰撞，降低模型复制占位符的出错率。报告格式校验失败最多重试一次，两次尝试共用原超时预算。
- 包版本为 0.3.0。配置与运行时依赖继续分离，报告处理器经构造参数传递。

### 验证

- 全套 65 项测试通过，含真实 Claude Code 2.1.299 的前台、后台及 auto 模式 SubagentHandback 三条链路。
- 三条链路均恰好显示 1 份中文最终报告，报告翻译失败数均为 0；原始报告仍为英文，子代理内部流式文本保持英文。
- 后台测试核对了任务通知直接传递，不作为中文用户输入再次翻译。自动 Handback 测试实际观察到该工具调用。
- 测试覆盖主/子代理识别、真实本地 HTTP 跳过路径、交接去重、恢复代理、超长报告失败回退、代码和路径保留。样本来自真实 Hook 事件，只有机器路径归一化；无 mock/stub/fake。
- 计数证据见 `VALIDATION.json`，真实事件样本见 `tests/fixtures/subagent_*.json`。
- 已安装 0.3.0，安装模块与验证源码逐文件哈希一致，默认 `claude` 入口回归通过。五角度独立审查及复审无遗留高置信 correctness 问题。

## 局限性

- 中文报告是主会话中的阅读副本，原工具结果仍为英文；不是把模型之间的协议改成中文。
- 不覆盖外部 CLI 启动的代理或 Agent Teams 的独立消息通道。部分版本原本就不对子代理内部消息触发 MessageDisplay，跳过计数为 0 不代表失效。
- 长报告受原有翻译长度限制和 Claude 原生 Hook 输出折叠规则约束；失败回退到英文。后台报告在主会话处理通知或下一次输入时显示。
- 已运行会话的 Hook 清单不自动热更新；安装后新启动的会话生效，可退出后使用 `claude --resume` 继续。没有重启用户正在运行的任务。
